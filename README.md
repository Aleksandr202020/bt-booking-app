# BT Booking

Онлайн-система записи клиентов на ручную автомойку **BT Automazgātava**.

- Одна мойка, один бокс, один клиент одновременно
- Все услуги длятся строго **60 минут**
- Основной интерфейс — мобильный
- Основной язык — **латышский**, с возможностью переключения на русский и английский

---

## 1. Роли

- **Customer** — только свои данные, автомобили, записи и уведомления
- **Admin** — полный доступ

---

## 2. Клиентская часть

**Возможности:**
- Регистрация / вход / выход
- Управление автомобилями (добавление, редактирование, удаление)
- Создание записи: автомобиль → услуга → дата → свободный слот → подтверждение
- Отмена своей записи **не позднее чем за 2 часа** до начала
- Перенос своей записи **не позднее чем за 10 минут** до начала
- Просмотр только **будущих и текущих** записей (историю прошедших не показывает)
- Кнопка «Добавить в календарь»
- Переключение языка (LV / RU / EN)

**Ограничения:**
- Максимум **1 запись на 1 автомобиль в день**
- Максимум **5 записей на 1 автомобиль за 30 дней**
- Запись максимум на **30 дней вперёд**

---

## 3. Административная часть (приоритет — телефон)

**Обязательные разделы и функции:**
- Dashboard «Сегодня»
- Календарь (день + неделя)
- Быстрый поиск клиента **по номеру телефона**
- Создание записи **без регистрации клиента** (ручной ввод имени, телефона, марки, модели, номера)
- Отмена и перенос любой записи
- Блокировка отдельных часов с причиной
- Праздничные дни
- Управление услугами и ценами (цены с центами)
- Управление категориями / марками / моделями
- Отметка **no-show**
- Настройка рабочего времени (разные часы по дням недели)

---

## 4. Ключевые бизнес-правила

- Цена определяется автоматически: автомобиль → категория → услуга → цена
- Цена **фиксируется** в записи (`price_cents`) в момент создания
- Изменение прайса не затрагивает старые записи
- Один бокс = одна активная запись на пересекающееся время (защита на уровне PostgreSQL)
- Все критические проверки выполняются только на сервере
- Idempotency key при создании записи

**Статусы записи:**
- `confirmed`
- `cancelled_by_customer`
- `cancelled_by_admin`
- `completed`
- `no_show`

- У клиента — кнопка «Добавить в календарь»
- SMS и полноценные in-app уведомления — позже

## 6. Основные таблицы (Neon PostgreSQL)

```
users
profiles
sessions
vehicle_categories
vehicle_makes
vehicle_models
cars
services
service_prices          -- service_id + category_id → price_cents
working_hours           -- по дням недели
holidays
blocked_slots
bookings
app_settings
notifications
audit_logs              -- только ключевые события
```

**Критические поля `bookings`:**
- `user_id` (nullable — для записей, созданных админом вручную)
- `car_id` (nullable)
- `service_id`
- `start_at`, `end_at` (timestamptz)
- `price_cents` (integer)
- `status`
- `idempotency_key` (unique)
- `created_by`
- `client_name`, `client_phone` (для ручных записей)
- `car_make`, `car_model`, `car_plate` (для ручных записей)

**Обязательно:** Exclusion constraint на активные записи по временному диапазону.

## 7. Этапы сборки

### Этап 1 — Стабилизация клиентской части
- Регистрация / вход / автомобили
- Каталог (категории, марки, модели, услуги, цены)
- Создание записи с фиксацией цены
- Серверные проверки + idempotency + защита от пересечений
- Ограничения (1 запись/день на авто, 5/30 дней, 30 дней вперёд)
- Отмена (2 часа) и перенос (10 минут)

### Этап 2 — Минимальная админка
- Dashboard «Сегодня»
- Календарь (день)
- Быстрый поиск по телефону
- Создание записи админом (в т.ч. без регистрации клиента)
- Блокировки часов + праздники
- Управление услугами и ценами
- Отмена / перенос админом
- Статус no-show

### Этап 3 — Доводка
- Недельный календарь
- Настройка рабочего времени по дням недели
- Google Calendar (владелец + кнопка у клиента)
- Базовый audit log
- Управление клиентами и автомобилями

### Этап 4+ (позже)
- SMS
- Полноценные in-app уведомления
- Расширенная статистика no-show
- Более тонкие роли
